# Marrow 4.2 Resubmission Design

Date: 2026-07-24
Status: Approved

## Goal

Marrow was rejected under App Store Guideline 4.2 (Minimum Functionality) on version 1.0
build 4. The spaced-repetition engine that makes the app novel is invisible to a reviewer:
they see a chrome-less vertical feed of text cards and conclude the app is too thin.

This change makes the engine visible and the app more "app-like" by adding three surfaces,
reusing the existing scheduler, feed, corpus, and store code underneath. It is purely
additive: no existing behavior (SRS scheduling, feed interleaving, card UI, local-only
posture) changes.

## Scope

In scope: onboarding, progress/stats screen, multi-select domain filter, persistence for the
first two, a slim navigation top bar, tests, and resubmission prep.

Out of scope: streaks, daily goals, "due today" push surfacing beyond the stats tile, corpus
changes, any network/analytics.

## Components

### 1. Persistence: settings table (`src/store`)

Add a small key-value `settings` table to the existing SQLite store (same `marrow.db`,
same `openStore`).

- Schema: `CREATE TABLE IF NOT EXISTS settings (key TEXT PRIMARY KEY NOT NULL, value TEXT NOT NULL);`
  added to the existing `DDL` string so the corruption-recovery path covers it too.
- New `Store` methods:
  - `getSetting(key: string): string | null`
  - `putSetting(key: string, value: string): void` (upsert)
- Callers serialize their own values. Keys used:
  - `onboardingDone` = `"1"` once completed.
  - `selectedDomains` = JSON array of `Domain` (e.g. `["cs","math"]`); absent/empty-handling
    treats "no stored value" as "all domains".
- `reset()` stays scoped to `card_state` only (settings such as onboarding completion are not
  user progress and should survive a data reset).

### 2. Stats compute module (`src/stats`)

A pure, dependency-injected module (mirrors `src/scheduler` / `src/feed` style) so it is unit
testable without a device.

- Input ports: a reader over `card_state` rows and the corpus (`loadCorpus` / per-domain
  counts). Reuse existing `StorePort`-style shape; add a `getAllStates(): CardState[]` reader
  to the store.
- Output: a `Stats` object:
  - `learned`: number of `card_state` rows (cards seen at least once).
  - `mastered`: count where `status === "review"`.
  - `dueToday`: count where `dueAt <= endOfTodayLocal` (or simply `dueAt <= now`; use `now`
    for determinism and to match the feed's own "due" definition).
  - `perDomain`: for each `Domain`, `{ seen, total }` where `total` is corpus count for that
    domain and `seen` is rows whose card id resolves to that domain.
- All counts derived at read time; no new tracking or migration.

### 3. Domain filtering (`src/feed`)

The feed currently draws new cards across all domains via `domainCursor`, and reviews across
all seen cards. Add an optional domain filter carried on `FeedDeps` (or `Session`):

- `takeNew` restricts its domain rotation to the selected set.
- `takeReview` filters out due cards whose domain is not selected (resolve each due card's
  domain via `corpus.getCard`).
- Empty/absent selection = all domains (current behavior).
- Changing the selection restarts the session via `createSession` (fresh feed).

### 4. Onboarding screen (`app/onboarding.tsx`)

Two full-screen panels shown once on first launch, gated on `getSetting("onboardingDone")`.

- Panel 1: "Scroll to learn one idea at a time." Explains the feed.
- Panel 2: names the spaced-repetition mechanic explicitly. Copy (no em dashes):
  "Marrow remembers what you've seen and brings each idea back right before you'd forget it.
  Grade how well you knew it, and the ones you find hard come back sooner." CTA: "Start
  learning."
- "Skip" affordance on panel 1.
- On completion/skip: `putSetting("onboardingDone", "1")` and route to the feed.
- Dark theme, matches existing nativewind styling.

### 5. Navigation top bar + stats screen

- A slim top bar rendered above the `FlatList` in `app/index.tsx`:
  - Left: domain label button (e.g. "All domains", "CS + Math") opening the domain sheet.
  - Right: a stats icon/button routing to `app/stats.tsx`.
  - Feed height math becomes `winHeight - insets.top - insets.bottom - barHeight` so paging
    still snaps to full cards.
- `app/stats.tsx`: a scrollable screen reading from `src/stats`.
  - Three big tiles: Learned, Mastered, Due today.
  - Per-domain breakdown rows (seen / total) for CS, Finance, Math, Science.
  - A back affordance (native stack header is disabled, so an explicit close button).
- Domain sheet: a modal/bottom-sheet component (`src/ui/DomainSheet.tsx`) with multi-select
  checkboxes (All + four domains). Applying a change persists `selectedDomains` and restarts
  the session.
- Register `stats` and `onboarding` routes in `app/_layout.tsx`. On cold start, if
  `onboardingDone` is unset, land on onboarding first.

## Data flow

Feed and stats both read `card_state` from the same SQLite store. Onboarding and the domain
filter read/write the `settings` table. Corpus is static JSON loaded once. No network anywhere.

## Testing

- Unit tests (extend `__tests__`):
  - Store: `getSetting`/`putSetting` upsert and null-on-missing; `reset()` leaves settings.
  - Stats: given synthetic `card_state` rows + corpus, correct `learned`/`mastered`/`dueToday`/
    `perDomain`.
  - Feed: with a domain filter, new cards and reviews only come from selected domains; empty
    selection behaves as all domains (no regression to existing feed tests).
- Manual: run in simulator, verify onboarding (first run only), top bar, domain sheet
  restarts feed, stats screen numbers move as you scroll/grade.
- Full suite (`npm test`) and `tsc` must pass before build.

## Resubmission

- Bump `ios.buildNumber` to `5` in `app.json`.
- `eas build -p ios --profile production` then `eas submit -p ios --latest` with the
  `EXPO_ASC_*` env vars (ASC API key already on disk). EAS also needs an Expo login.
- Reviewer note: point at onboarding, the stats screen, and the domain filter, and name the
  spaced-repetition mechanic. Reply on the existing rejection thread and submit build 5 for
  review. This is the one irreversible outward step and is confirmed with the user first.

## Non-goals / risks

- Card accuracy (finance domain) is a separate, pre-existing risk not addressed here.
- No copy anywhere uses em dashes (user preference).

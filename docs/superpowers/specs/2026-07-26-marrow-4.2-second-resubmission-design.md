# Marrow 4.2, second resubmission: from a feed to a learning tool

Date: 2026-07-26
Status: implemented

## Why

Build 6 was rejected under Guideline 4.2 (Minimum Functionality) with "the issues we
previously identified still need your attention", reviewed on an iPad Air 11-inch (M3).
The first round added onboarding, a progress screen and a domain filter. That was not
enough: the app was still one screen, and everything a user could do was scroll a feed
and grade a card.

The gap is not polish. A reviewer opening the app could not *do* anything except
consume a linear feed. Everything the corpus and the scheduler already knew, 230 cards
and a full review history, was unreachable.

## What was added

Five surfaces, joined by a bottom tab bar, all reading the data the app already had.

**Feed (existing, extended).** Still the vertical feed. Each card now offers save and
"Open concept". The top bar shows a live count of cards ready for review, which makes
the scheduler visible on the first screen instead of only inside Progress.

**Library (new).** Browse and full-text search all 230 concepts. Ranked search across
title, topic, tags, prompt, answer and body, with AND semantics so a second word
narrows. Filter by subject, by learning state (Due / Unread / Learning / Mastered) and
by saved. Two-up grid on a tablet.

**Concept detail (new).** The full explanation, a self-test that reveals and grades into
the real schedule, the card's own review stats (next review, reps, lapses, interval),
tags, tappable sources, and related concepts scored by shared topic and tags.

**Quiz (new).** Pick subjects and a length, then run a scored quiz drawn in tiers: cards
already due first, then seen-but-not-due, then unseen. Ends with a percentage, the list
of missed cards, and a one-tap retry of only those.

**Progress (rewritten).** Daily goal with progress, day streak, learned / mastered / due
tiles, recall accuracy, a 28-day activity chart, and per-subject coverage.

**Settings (new).** Daily goal, replay the intro, clear saved cards, reset progress,
privacy and support links, and a plain statement that nothing leaves the device.

## Data

Two new tables, both created with `IF NOT EXISTS` so an existing install upgrades in
place with its progress intact:

- `review_log(id, cardId, grade, at)` - append-only. `card_state` holds only each
  card's latest snapshot, so it cannot answer "how many reviews on Tuesday". Streak,
  activity chart and accuracy all read this.
- `bookmarks(cardId, createdAt)`.

`reset()` clears progress and its history. Bookmarks and settings are saved content and
preferences rather than progress, so they survive it.

Still fully on-device: no account, no network, no collection. The "Data Not Collected"
privacy label is unchanged.

## iPad

The rejection came from an iPad. Expo's `orientation: "portrait"` already maps to
iPhone-portrait plus every iPad orientation, so rotation was available and unhandled.
`src/ui/layout.ts` is now the single source of size-class truth: a centred reading
column caps line length instead of stretching a sentence across the display, gutters
widen, the Library becomes a two-up grid, and Progress lays its tiles out in one row.

## Out of scope

Push notifications and reminders (would add a permission prompt and a config plugin for
little review benefit), and new corpus cards. 230 hand-written concepts across four
subjects is already substantial; the gap Apple named was reachable functionality.
